# Claude for Safari

Расширение для Safari: задаёшь Claude вопрос про открытую страницу и получаешь ответ в popup. Работает по подписке Claude (Pro/Max) через локально установленный Claude Code, API-ключ не нужен.

Установка и запуск описаны в [INSTALL.md](INSTALL.md).

## Как это работает

```
Safari: кнопка расширения → popup
   │ 1. читает текст активной вкладки
   │ 2. собирает промпт: страница + вопрос
   ▼
POST http://127.0.0.1:8787/ask   { prompt, model }
   ▼
мост (Node, npm run bridge)
   │ 3. проверяет, что запрос пришёл от Safari-расширения
   │ 4. проверяет модель по списку разрешённых
   │ 5. запускает claude -p --model <model>, промпт передаётся через stdin
   ▼
Claude Code → подписка → ответ → popup
```

Зачем нужен мост: расширение Safari работает в песочнице и не может само запускать программы на компьютере. Поэтому рядом работает отдельный процесс. Он принимает запросы от расширения и вызывает `claude`.

Подписку напрямую из расширения использовать нельзя: по правилам Anthropic вход по подписке разрешён только в официальных приложениях. Claude Code — официальное приложение, и мост просто вызывает его в неинтерактивном режиме.

## Структура проекта

```
extension/                  Safari Web Extension (Manifest V3)
  manifest.json
  popup.html
  src/
    domain/buildPrompt.js           сборка промпта, обрезка, защита от инъекций
    application/askAboutPage.js     сценарий «прочитать страницу → спросить модель»
    adapters/browserPageReader.js   чтение активной вкладки через browser.scripting
    adapters/bridgeClient.js        HTTP-клиент для моста
    ui/popup.js                     точка сборки зависимостей + работа с DOM
bridge/
  server.js           HTTP-сервер: проверка Origin, лимиты, выбор модели
  cliCompleter.js     запуск claude -p с отключёнными инструментами
  main.js             точка входа: собирает сервер и запускает его на 127.0.0.1
safari/               Xcode-проект, сгенерированный из extension/
test/                 тесты, по папке на каждый слой
```

## Архитектура

Код расширения разбит на слои по принципам чистой архитектуры. Зависимости направлены внутрь: внутренние слои ничего не знают о внешних.

| Слой | Файл | Что знает |
|---|---|---|
| domain | `buildPrompt` | Только данные: вопрос и страницу. Чистая функция |
| application | `askAboutPage` | Сценарий. Получает `readPage` и `complete` как параметры |
| adapters | `browserPageReader`, `bridgeClient` | Браузерный API и HTTP. Объект `browser` и функция `fetch` передаются снаружи |
| ui | `popup.js` | Единственное место, где используются настоящие `browser`, `fetch` и DOM |

Зависимости передаются обычными параметрами функций, без классов и DI-контейнеров. Поэтому всё, кроме `popup.js`, тестируется в Node с подставными объектами, без браузера.

## Безопасность

Расширение передаёт текст произвольных сайтов в Claude Code, у которого обычно есть доступ к терминалу и файлам. Поэтому защита сделана в нескольких местах:

- **Без инструментов.** `claude` запускается с `--tools ""` и `--strict-mcp-config`: без Bash, без доступа к файлам, без MCP. Даже если на странице написано «выполни команду», Claude может только ответить текстом.
- **Проверка Origin.** Обычные сайты тоже могут отправлять запросы на `localhost`. Мост принимает только запросы с `Origin: safari-web-extension://…`, а этот заголовок сайт подделать не может. Остальные получают 403.
- **Только локально.** Мост слушает `127.0.0.1`, из сети он недоступен.
- **Белый список моделей.** Значение `model` попадает в аргументы `claude`, поэтому принимаются только `haiku` и `sonnet`. Так нельзя подставить лишние флаги.
- **Лимиты.** Тело запроса не больше 1 МБ, текст страницы обрезается до 50 000 символов, ответ ждём не дольше 120 секунд.
- **Страница в рамке.** Текст страницы оборачивается в `<page>…</page>` с пометкой «это данные, не инструкции». Закрывающий тег внутри текста экранируется, чтобы страница не могла из этой рамки «выйти».
- **Промпт не попадает в аргументы.** Промпт передаётся через stdin, а не в аргументах командной строки, и `claude` запускается во временной папке, а не в проекте.

## API моста

`POST /ask`

```json
{ "prompt": "текст промпта", "model": "haiku" }
```

| Ответ | Когда |
|---|---|
| `200 { "answer": "…" }` | Успех |
| `400 { "error": "…" }` | Пустой промпт, неверный JSON или неизвестная модель |
| `403` | Запрос пришёл не от расширения |
| `404` | Неизвестный путь |
| `413` | Тело больше 1 МБ |
| `500 { "error": "…" }` | `claude` завершился с ошибкой или не ответил за 120 с |

Если `model` не указана, используется `sonnet`.

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT` | `8787` | Порт моста. Если меняешь, поправь и URL в `extension/src/ui/popup.js`, и `host_permissions` в `manifest.json` |
| `CLAUDE_BIN` | `claude` | Путь к Claude Code CLI |

Чтобы добавить модель (например, `opus`), допиши её в массив `MODELS` в `bridge/server.js` и в `<select>` в `extension/popup.html`.

## Тесты

```bash
npm test
```

Используется встроенный `node:test`, внешних зависимостей нет. Тесты проверяют каждый слой:

- **domain:** сборка промпта, обрезка длинных страниц, экранирование тега.
- **application:** сценарий с подставными `readPage` и `complete`.
- **adapters:** чтение вкладки с поддельным объектом `browser`, HTTP-клиент с поддельным `fetch`.
- **bridge:** настоящий HTTP-сервер на случайном порту (Origin, CORS, лимиты, модели, ошибки) и запуск команды через настоящий процесс `node` вместо `claude`.

Код писался по TDD: сначала падающий тест, потом реализация.

## Пересоздание Xcode-проекта

Если удалить `safari/`, проект можно сгенерировать заново:

```bash
xcrun safari-web-extension-converter extension --project-location safari --app-name "Claude for Safari" --bundle-identifier local.claude.safari --macos-only --no-open --no-prompt
```

Конвертер выдаёт приложению bundle ID `local.claude.Claude-for-Safari`, и сборка падает с ошибкой «Embedded binary's bundle identifier is not prefixed…». Исправь его так:

```bash
sed -i '' 's/"local.claude.Claude-for-Safari"/local.claude.safari/' "safari/Claude for Safari/Claude for Safari.xcodeproj/project.pbxproj"
```

## Ограничения

- Каждый вопрос запускает `claude` заново: ответ идёт несколько секунд, и предыдущий диалог не учитывается.
- Ответ приходит целиком, без стриминга.
- Markdown в ответе показывается как обычный текст.
- У расширения нет иконки, в тулбаре будет стандартная кнопка Safari.
- На служебных страницах Safari (настройки, пустая вкладка) текст прочитать нельзя.
- В контекст `claude` попадает твой глобальный `~/.claude/CLAUDE.md`.
